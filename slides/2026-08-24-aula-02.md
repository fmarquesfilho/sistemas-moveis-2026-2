# O problema que a plataforma cria

O mesmo aplicativo, duas vezes:

```
   Android              iOS
   Kotlin               Swift
   Jetpack Compose      SwiftUI
   Android Studio       Xcode
   Play Console         App Store Connect
```

> Duas bases de código, duas equipes, dois cronogramas — para **o mesmo produto**. É desse custo que nascem todas as soluções multiplataforma.

---

# As três respostas

| Abordagem | Como funciona | Custo |
|---|---|---|
| **Nativo** | Uma base por plataforma | Máximo controle, máximo esforço |
| **Web embarcada** | HTML dentro de um invólucro nativo | Barato, mas distante do sistema |
| **Compilado ou compartilhado** | Uma base, saída nativa | Um ecossistema a aprender |

> É no terceiro grupo que Flutter, React Native e Kotlin Multiplatform disputam. Nenhuma das três respostas é errada — cada uma resolve um contexto.

---

# Onde cada um traça a fronteira

```
  Flutter        │ lógica + interface compartilhadas, desenhadas por Skia
  React Native   │ lógica em JavaScript, componentes nativos da plataforma
  KMP + Compose  │ lógica em Kotlin; interface compartilhada ou nativa
```

A diferença que importa: em KMP, **compartilhar a interface é opcional**.

> Você pode compartilhar só a lógica e escrever a tela em Jetpack Compose e SwiftUI, ou compartilhar tudo com Compose Multiplatform. A mesma tecnologia atende às duas decisões.

# Kotlin Multiplatform

Um módulo Kotlin compilado para várias plataformas:

```
  commonMain/     código que roda em todo lugar
     │
     ├── androidMain/   implementações específicas de Android  (JVM)
     ├── iosMain/       implementações específicas de iOS      (nativo)
     └── jvmMain/       alvo desktop, para desenvolver rápido
```

Quando algo só existe numa plataforma, o código comum **declara** e cada plataforma **implementa**:

```kotlin
expect fun idDoDispositivo(): String        // commonMain: declara
actual fun idDoDispositivo(): String = ...  // androidMain: implementa
```

---

# Compose Multiplatform

A interface, também em `commonMain`:

```kotlin
@Composable
fun Saudacao(nome: String) {
    Column(modifier = Modifier.padding(16.dp)) {
        Text("Olá, $nome", style = MaterialTheme.typography.headlineMedium)
        Button(onClick = { /* ... */ }) { Text("Continuar") }
    }
}
```

É a **mesma API** do Jetpack Compose do Android, estendida a iOS, desktop e web.

> Quem escrever para Android está aprendendo Compose Multiplatform sem saber. Não são duas coisas.

# Kotlin em uma frase

Linguagem de tipagem estática que roda na JVM, compila para nativo e para JavaScript, com **null safety** no sistema de tipos.

```kotlin
fun main() {
    val nome = "turma"
    println("Olá, $nome")
}
```

> O objetivo dos próximos 30 minutos não é dominar Kotlin. É reconhecer as construções que vamos usar o semestre inteiro. Acompanhe colando no **Playground**.

# Variáveis e tipos

```kotlin
val nome: String = "Ana"     // imutável, não pode ser reatribuída
var contador = 0             // mutável; o tipo é inferido
contador += 1

val precos = listOf(9.90, 24.50)     // List<Double>, imutável
val total: Double = precos.sum()

const val BASE_URL = "https://api.exemplo.br"   // constante de compilação
```

> Na dúvida, use **`val`**. Em Compose, quase tudo é imutável por padrão, e estado mutável é declarado de forma explícita.

---

# Null safety

```kotlin
var titulo: String = "Vistoria"
// titulo = null                    ← não compila

var apelido: String? = null         // o ? admite nulo

val tamanho = apelido?.length ?: 0  // chamada segura e valor padrão

apelido?.let { println(it.uppercase()) }   // só executa se não for nulo
```

> O compilador **não deixa você esquecer**. Tipos anuláveis e não anuláveis são tipos diferentes, e a conversão tem de ser explícita.

---

# Coleções

```kotlin
val numeros = listOf(1, 2, 3, 4, 5)

val pares = numeros.filter { it % 2 == 0 }        // [2, 4]
val dobros = numeros.map { it * 2 }               // [2, 4, 6, 8, 10]
val soma = numeros.fold(0) { acc, n -> acc + n }  // 15

val porTipo = numeros.groupBy { if (it % 2 == 0) "par" else "ímpar" }

val mutavel = mutableListOf("a")
mutavel += "b"
```

> `it` é o nome implícito do único parâmetro de uma lambda. Listas são **imutáveis por padrão**; a versão mutável tem nome próprio.

# Funções

```kotlin
fun somar(a: Int, b: Int): Int = a + b            // corpo de expressão

fun saudar(nome: String, saudacao: String = "Olá") =   // valor padrão
    "$saudacao, $nome"

saudar(nome = "Ana")                       // parâmetro nomeado
saudar("Ana", saudacao = "Bom dia")

fun aplicar(x: Int, f: (Int) -> Int) = f(x)    // função como parâmetro
aplicar(3) { it * it }                          // 9
```

> Você vai ver **parâmetros nomeados** o tempo todo. É o que torna a árvore de componentes do Compose legível.

# Classes e data classes

```kotlin
data class Vistoria(
    val id: String,
    val endereco: String,
    val sincronizada: Boolean = false
)

val v = Vistoria(id = "1", endereco = "Rua A")
val enviada = v.copy(sincronizada = true)      // cópia com alteração

println(v)              // Vistoria(id=1, endereco=Rua A, sincronizada=false)
println(v == enviada)   // false — igualdade por valor
```

> `data class` gera `equals`, `hashCode`, `toString` e `copy`. O padrão **`copy`** aparece muito: objetos imutáveis se "modificam" produzindo uma cópia.

---

# Classes seladas

```kotlin
sealed interface EstadoDaTela {
    data object Carregando : EstadoDaTela
    data class Sucesso(val itens: List<Vistoria>) : EstadoDaTela
    data class Erro(val mensagem: String) : EstadoDaTela
}
```

O compilador conhece **todas** as implementações possíveis.

> É exatamente esse padrão que vamos usar na Sprint 2 para modelar o estado de cada tela. Carregando, sucesso e erro deixam de ser combinações de booleanos soltos.

---

# `when` como expressão

```kotlin
val texto = when (estado) {
    is EstadoDaTela.Carregando -> "Carregando…"
    is EstadoDaTela.Sucesso    -> "${estado.itens.size} vistorias"
    is EstadoDaTela.Erro       -> estado.mensagem
}
```

Dentro de cada ramo, `estado` já tem o tipo específico: não é preciso converter.

> Esqueceu um caso? Com uma classe selada, **não compila**. Essa é a garantia que faz valer a pena modelar estado assim.

# Extensões e funções de escopo

```kotlin
fun String.primeiraMaiuscula() =                 // extensão
    replaceFirstChar { it.uppercase() }

"vistoria".primeiraMaiuscula()                   // "Vistoria"

val config = Configuracao().apply {              // apply: configura e devolve
    tempoLimite = 30
    tentativas = 3
}

val n = texto?.let { it.length } ?: 0            // let: transforma se não-nulo
```

> Extensões acrescentam comportamento a um tipo **sem herdar dele**. É assim que boa parte das bibliotecas Kotlin é construída.

# Assíncrono: `suspend` e coroutines

```kotlin
suspend fun carregarVistorias(): List<Vistoria> {
    delay(500)                       // suspende, não bloqueia a thread
    return repositorio.buscarTodas()
}

viewModelScope.launch {
    val lista = carregarVistorias()  // parece sequencial, não bloqueia
    _estado.value = EstadoDaTela.Sucesso(lista)
}
```

Uma função `suspend` só pode ser chamada de dentro de outra `suspend` ou de um escopo de coroutine.

> **Concorrência estruturada**: toda coroutine pertence a um escopo, e cancelar o escopo cancela tudo o que ele iniciou. É o que evita trabalho órfão quando a tela fecha.

---

# `Flow`: valores ao longo do tempo

```kotlin
val vistorias: Flow<List<Vistoria>> = banco.observarTodas()

viewModelScope.launch {
    vistorias.collect { lista ->
        _estado.value = EstadoDaTela.Sucesso(lista)
    }
}
```

- `suspend` devolve **um** valor, no futuro
- `Flow` devolve **muitos**, conforme mudam

> Toda leitura de banco e toda escuta de mudança em Compose passa por aqui. Voltamos a isso com força na Sprint 3.

# Juntando tudo: uma tela

```kotlin
@Composable
fun TelaVistorias(estado: EstadoDaTela) {
    when (estado) {
        is EstadoDaTela.Carregando -> CircularProgressIndicator()
        is EstadoDaTela.Erro       -> Text(estado.mensagem)
        is EstadoDaTela.Sucesso    -> LazyColumn {
            items(estado.itens) { v -> Text(v.endereco) }
        }
    }
}
```

Classe selada, `when` exaustivo e função `@Composable` — as três construções de hoje, numa tela só.

> A tela é **função do estado**. Mudou o estado, o Compose redesenha o que for necessário. É o assunto de **31/08 e 02/09**, as duas aulas em que construímos a tela da entrega.
